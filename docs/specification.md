# 要件定義書：図書館蔵書管理システム（改訂版 v1.4）

## Why（なぜ作るか）

### 現状の課題

現在、A市立図書館の貸出・返却管理は紙台帳で行っており、以下の課題が発生している：

1. **業務効率の低下**：
   - 貸出処理に平均5分、在庫確認に平均3分を要している
   - 月間約3,000件の貸出に対し、司書の作業時間が400時間（約50人日）

2. **利用者の利便性低下**：
   - 在庫状況の確認に窓口での問い合わせが必要
   - 予約機能がないため、人気書籍の借り逃しが発生

3. **データの不正確性**：
   - 台帳の記入漏れにより、年間約50冊（蔵書の約0.5%）の所在不明が発生
   - 延滞図書の追跡が困難で、督促が不十分

### 期待される効果

1. **業務効率化**：貸出処理時間を60%削減（5分→2分）、司書の作業時間を月間240時間に削減
2. **利用者満足度向上**：オンライン検索・予約機能により利便性を向上
3. **蔵書管理の精度向上**：所在不明図書を年間10冊以下（0.1%以下）に削減
   ※前提: 年1回の物理棚卸し実施を運用要件とする

### 成功指標（KPI）

| KPI | 目標値 | 測定方法 |
|-----|--------|---------|
| 貸出業務処理時間 | 平均2分以内 | 利用者来館から貸出完了までの業務時間（手動ステップ含む） |
| API応答時間 | 平均1秒以内（P95） | 各APIエンドポイントのレスポンスタイム |
| システム稼働率 | 99.5%以上 | 月次計測 |
| 利用者満足度 | アンケートで80%以上が「満足」 | 年次アンケート |
| 所在不明図書 | 年間10冊以下 | 年次棚卸し時の差異 |

## What（何をするか）

### 0. 基本定義

#### 0.1 入力値の形式ルール

- **利用者ID・書籍ID・貸出ID・予約ID**：1以上の整数。DBのAUTOINCREMENTまたはシーケンスで自動発行。ユーザーが入力することはない。
- **メールアドレス**：RFC 5322に準拠した形式であること。
- **ISBN**：ISBN-10またはISBN-13形式を受け付ける。ハイフンの有無は問わない。検索時は内部でハイフンを除去して比較する（ISBN-10/13の相互変換は行わない）。
- **日時の保存**：システム内部ではすべてUTCで保存する。
- **電話番号**：ハイフンあり・なしを両方許容する。ハイフン除去後に10〜11桁の数字であること。保存時にハイフンを除去して保存する。

#### 0.2 タイムゾーン戦略

- システム内部の日時はすべてUTCで保存・処理する。
- 利用者への表示はJST（UTC+9）に変換して行う。
- 「当日」「翌日」などの日付判定はJST基準で行う。

#### 0.3 書籍状態の定義

書籍は以下の3つの状態のいずれかを取る：

| 状態名（日本語） | コード値 | 説明 |
|----------------|---------|------|
| 貸出可能 | `AVAILABLE` | 図書館に在庫があり、貸出できる状態 |
| 貸出中 | `CHECKED_OUT` | 利用者が借りており、まだ返却されていない状態 |
| 予約者受取待ち | `RESERVED_PICKUP_WAITING` | 返却済みで予約者に通知済みだが、予約者がまだ受け取りに来ていない状態 |

#### 0.4 状態遷移規則

| 現在の状態 | 操作 | 遷移後の状態 |
|-----------|------|-------------|
| 貸出可能 | 貸出操作 | 貸出中 |
| 貸出中 | 返却（予約なし） | 貸出可能 |
| 貸出中 | 返却（予約あり） | 予約者受取待ち |
| 予約者受取待ち | 予約者が貸出 | 貸出中 |
| 予約者受取待ち | 予約期限切れ（自動処理） | 貸出可能 |
| 予約者受取待ち | 予約キャンセル | 貸出可能 |

**自動処理の定義**: 「予約期限切れ（自動処理）」は§6で定義される延滞管理バッチが担当する。バッチは24時間間隔で実行され、予約通知日時（UTC）から72時間（3×24時間）が経過した `RESERVED_PICKUP_WAITING` 書籍を `AVAILABLE` に変更する。

#### 0.5 アカウント状態の定義

利用者アカウントは `有効（active）` または `無効（inactive）` の二値フラグを持つ。
登録時はデフォルトで `有効（active）`。`無効（inactive）` の利用者は貸出・予約・検索の実行権限を持たないが、履歴データは保持される。本仕様書で「利用者」と記述する場合、特に断りがない限り `有効（active）` な利用者を指す。

#### 0.6 システム定数

| 定数名 | 値 | 説明 |
|--------|-----|------|
| 同時貸出上限 | 3冊 | 利用者が同時に借りられる最大冊数 |
| 貸出期間 | 14暦日 | 借りた日から返却期限までの日数（暦日） |
| 予約取置き期間 | 3暦日 | 予約者への通知から受取期限までの日数（暦日） |
| 延滞アラート閾値 | 7暦日 | 返却期限を過ぎてからアラートを送るまでの日数 |
| 延滞チェック間隔 | 24時間 | 延滞チェックバッチを実行する間隔 |
| 同時予約上限 | 5冊 | 利用者が同時に予約できる最大冊数 |

### 1. 利用者登録

#### 1.1 機能概要

利用者は氏名・メールアドレス・電話番号を入力して会員登録を行う。
登録が完了すると、利用者IDが自動発行される。登録完了メールは、トランザクション確定後に非同期で送信される（§1.5・§1.6参照）。
**本APIは認証不要（匿名アクセス可能）とする。**
利用者情報の更新・退会機能は別途定義する（§8で予定）。

#### 1.2 入力項目

| 項目名 | 必須 | 制約 | 備考 |
|--------|------|------|------|
| 氏名 | 必須 | 1文字以上100文字以内 | 全角・半角を許容 |
| メールアドレス | 必須 | RFC 5322準拠 | 有効（active）アカウント間で重複不可 |
| 電話番号 | 必須 | ハイフン除去後10〜11桁の数字 | ハイフンあり・なし両方許容 |

#### 1.3 入力値の検証ルール

以下の条件をすべて満たすこと：

- 氏名は1文字以上100文字以内であること
- メールアドレスはRFC 5322に準拠した形式であること
- 電話番号はハイフンを除去した後、10桁または11桁の数字のみで構成されていること

バリデーションエラーが複数同時に発生した場合、すべての失敗した検証条件のエラーメッセージをリスト形式で一括して返す。エラーレスポンスは以下の形式とする：
```json
{"errors": [{"field": "name", "message": "〇〇"}, ...]}
```

いずれかの条件を満たさない場合、400 Bad Requestを返し、登録を行わない。

#### 1.4 重複登録の制約

`有効（active）` な利用者の中に、同じメールアドレスで登録済みのアカウントが存在する場合、新規登録は行わない。その際は409 Conflictを返し、既存の利用者IDを提示してログイン画面への誘導を促す。

`無効（inactive）` のアカウントが存在する場合：
- APIは 409 Conflictを返し、レスポンスボディに `{"action": "reactivate_or_new", "existing_user_id": <既存ID>}` を含める。
  （409の使用はプロジェクトポリシーとして採用。inactive重複は「再アクティブ化かどうかの選択を必要とする状態」として競合と見なす。）
- 利用者が **再アクティブ化に同意** した場合：`POST /users/{existing_user_id}/reactivate` を呼び出す。本エンドポイントの認証要件は§7で定義する。定義前の暫定仕様として、直前の `POST /users` レスポンスで受け取った `existing_user_id` との一致のみを検証する。既存アカウントを `有効（active）` に変更し、新しいIDは発行しない。
- 利用者が **拒否（新規登録を選択）** した場合：`POST /users` に `{"force_new": true}` を付加して再送する。新規の利用者IDを発行して別アカウントとして登録する。旧アカウントは `無効（inactive）` のまま維持される。

#### 1.5 登録成功時の処理

1. 新しい利用者IDをDBのAUTOINCREMENTまたはシーケンスで自動採番する
2. 電話番号のハイフンを除去して保存する
3. 登録日時としてシステムの現在日時（UTC）を記録する
4. アカウントを `有効（active）` 状態で作成する
5. 登録完了メールを非同期で送信する（トランザクション確定後）

登録完了メールの仕様：
- 件名：「【図書館システム】会員登録が完了しました」
- 内容：利用者ID、ログインURL、利用開始の案内
- 送信失敗時はリトライ（最大3回）。待機時間は前回試行の失敗時点から計測し、1回目失敗から60秒後・2回目失敗から120秒後・3回目失敗から240秒後に次回試行を実行する
- 3回失敗後はシステム管理者メールアドレス（設定ファイルで定義）へアラートメールを送信し、手動対応を依頼する。アラートメールには対象利用者ID・対象メールアドレス・失敗回数・最後のエラー内容を含める。アラート送信自体が失敗した場合はシステムログにERRORレベルで記録する

#### 1.6 同時実行制御

同一メールアドレスによる同時登録が発生した場合、メールアドレスに対する `有効（active）` アカウント行のみを対象としたpartial unique index（例: `CREATE UNIQUE INDEX ON users(email) WHERE status='active'`）により後からの登録が弾かれ、重複エラーとして処理される。DB制約違反による重複エラーは§1.4の「重複あり・`有効（active）`」と同一のHTTPステータス（409 Conflict）・同一のレスポンス形式で返す。クライアントはどちらの経路で発生した409かを区別する必要はない。
ユーザーレコードの挿入と通知ログの挿入は同一トランザクション内で行い、どちらかが失敗した場合は両方をロールバックする。
メール送信はトランザクション完了後に非同期で実行する。

### 2. 蔵書検索

#### 2.1 機能概要

有効（active）な利用者および司書（※司書の権限定義は別途§8管理者機能で定義。§8が定義されるまでの暫定措置として、司書と一般利用者の検索権限は同一とする）は、タイトル・著者名・ISBNのいずれかまたは組み合わせで蔵書を検索できる。
検索結果には在庫状況と、貸出中の場合は返却予定日、予約者受取待ちの場合は予約取置き期限が表示される。

**APIエンドポイント**: `GET /books`
**認証要件**: 本APIは認証必須とする。認証方式は§7で定義する。未認証リクエストへは401 Unauthorizedを返す（暫定）。

#### 2.2 検索条件

| 検索項目 | JSONパラメータ名 | 検索方法 | 詳細 |
|---------|--------------|---------|------|
| タイトル | `title` | 部分一致 | 大文字小文字を区別しない |
| 著者名 | `author` | 部分一致 | 大文字小文字を区別しない |
| ISBN | `isbn` | 完全一致 | 内部でハイフンを除去して比較（§0.1参照） |

複数の検索条件が指定された場合はAND条件で絞り込む。
検索条件が一つも指定されていない場合は400 Bad Requestを返し、全件取得は行わない。エラーレスポンス形式：`{"errors": [{"field": "query", "message": "検索条件を1つ以上指定してください"}]}`

**ページネーション**: 検索結果は最大100件を1ページとしてページネーションする。レスポンス形式：
```json
{"total": <総件数>, "page": <現在ページ番号>, "per_page": 100, "books": [...]}
```
デフォルトのソート順は「書籍ID昇順」。ページ指定は `?page=<1以上の整数>` クエリパラメータで行う。`page` が1未満の場合は400 Bad Requestを返す。`page` が総ページ数を超える場合は空の `books` 配列と正しい `total` を返す。

**インデックス運用要件**: 部分一致検索の対象カラム（title・author）には、データベースの全文検索インデックスまたはLIKEインデックスを適用することを運用要件とする。

#### 2.3 検索結果の表示項目

| 項目名 | JSONフィールド名 | 説明 |
|--------|---------------|------|
| 書籍ID | `book_id` | 蔵書の識別番号 |
| タイトル | `title` | 書籍のタイトル |
| 著者名 | `author` | 著者名 |
| ISBN | `isbn` | ハイフンを含む元の形式で表示 |
| 出版社 | `publisher` | 出版社名（未登録の場合は空欄） |
| 出版年 | `published_year` | 出版年（未登録の場合は空欄） |
| 在庫状況 | `status` | `AVAILABLE` / `CHECKED_OUT` / `RESERVED_PICKUP_WAITING` |
| 返却予定日 | `return_due_date` | `CHECKED_OUT` の場合はJST日付文字列（例: `"2026-06-12"`）、それ以外は `null` |
| 予約取置き期限 | `reservation_pickup_deadline` | `RESERVED_PICKUP_WAITING` の場合はJST日付文字列、それ以外は `null` |

各書籍オブジェクトには常に `return_due_date` と `reservation_pickup_deadline` の両フィールドを含める。値が該当しない状態では `null` を返す。
